# 2. KneadData

KneadData trims reads, filters tandem repeats, and removes host-aligned reads.
FORM's program-selected host reference is **hg39T2T**, the Huttenhower Lab
Bowtie2 **v0.2** bundle from assembly **GCA_009914755.4 / T2T-CHM13v2.0**.
Cleaned reads feed microbial/viral profiling and can optionally feed MEDI.

**State:** profiling is imported through bioBakery. The software and defaults
below were inspected in the existing candidate DNAnexus image and neighboring
workflow sources. They do not establish that the pending FORM deployment has
already adopted T2T or completed its validation.

## Runtime flags and precedence

Runtime behavior comes from three layers: the Nextflow process generates the
KneadData command; the selected site supplies image/reference locations and task
resources; KneadData supplies defaults for flags the command does not set.

FORM includes bioBakery defaults before FORM settings. A selected site then
overrides the relevant settings, followed by the run YAML and pipeline CLI
parameters. Within the inspected command, `kneaddata_options` is appended last.
It can pass nested tool options and can replace earlier scalar arguments if the
same option is repeated. Keep resource and input flags aligned with the process
allocation instead of accidentally overriding them in that string.

### Flags generated by the workflow

| Setting / flag | Inspected default | Effect |
| --- | --- | --- |
| `run_qc` | `true` | Enables the QC branch |
| Single-end input | `--unpaired <reads>` | One input file |
| Paired-end input | `-i1 <R1> -i2 <R2>` | Mate files from the sample channel |
| Host input | `--reference-db <directory>` | One flag per configured reference; FORM MGX selects its host reference |
| Output | `--output ./ --output-prefix <sample>_kneaddata` | Writes into the task working directory |
| Task threads, single-end | `--threads ${task.cpus}` | Nested tools use the allocated CPU count; `--processes` keeps KneadData's default of 1 |
| Task threads, paired-end | `--processes ${task.cpus}`, no `--threads` | Nested tools use KneadData's default of **1 thread**. The `form_docker` profile appends `--threads 8 --processes 1` to use the task allocation without multiplying it |
| `kneaddata_bypass_trim` | `false` | `--bypass-trim` is omitted; trimming runs |
| `kneaddata_remove_intermediate_files` | `true` | Adds `--remove-intermediate-output` |
| `kneaddata_options` | Empty string | No additional tool options unless supplied in the YAML/site config |
| Host reference check | `form_host_check: true` | FORM stops the run before any task if a local `host_genome` lacks `GCA_009914755.4_T2T.*.bt2` |
| Minimum versions | `form_min_kneaddata: 0.12`, `form_min_bowtie2: 2.5.5` | FORM stops the run after the first KneadData task reports an older version |

The paired-end command that bioBakery generates is equivalent to this template
before task-specific values are substituted:

```bash
kneaddata \
  -i1 SAMPLE_R1.fastq.gz -i2 SAMPLE_R2.fastq.gz \
  --reference-db HOST_INDEX_DIRECTORY \
  --output ./ --output-prefix SAMPLE_kneaddata \
  --processes ALLOCATED_CPUS \
  --remove-intermediate-output
```

With `-profile local,form_docker`, `--threads 8 --processes 1` is appended after
these arguments, because `kneaddata_options` is added last.

After KneadData, the wrapper compresses FASTQ outputs using
`pigz -p ${task.cpus}`. For paired input it concatenates the two cleaned mate
files and both unmatched files into a single compressed file for downstream
profiling, while publishing the individual paired/unmatched outputs. This
concatenation is a wrapper operation; it does not use `--cat-final-output`.

### Trimmomatic defaults inside the image

Trimming is enabled. The image's KneadData configuration selects **NexteraPE**
adapters and Phred+33 quality scores unless the YAML changes those choices.
KneadData launches Java with `-Xmx500m`, selects `PE` or `SE`, and forwards its
thread count and `-phred33`.

The automatically constructed trimming operations, in order, are:

| Step | Paired-end setting | Single-end setting |
| --- | --- | --- |
| Initial length filter | `MINLEN:60` | `MINLEN:60` |
| Adapter clipping | `ILLUMINACLIP:<adapter-dir>/NexteraPE-PE.fa:2:30:10:8:TRUE` | `ILLUMINACLIP:<adapter-dir>/NexteraPE-PE.fa:2:30:10` |
| Quality trimming | `SLIDINGWINDOW:4:20` | `SLIDINGWINDOW:4:20` |
| Final length filter | `MINLEN:floor(0.5 × L)` | `MINLEN:floor(0.5 × L)` |

`L` is the length of the **first sequence in the first input FASTQ**, read after
decompression/header handling. It is not a fixed 50-base threshold or a
cohort-wide read-length estimate. For a 150-base first read, the final operation
is `MINLEN:75`. The single-end NexteraPE adapter filename above reflects the
inspected implementation. Its adapter directory is
`/opt/conda/lib/python3.8/site-packages/kneaddata/adapters`.

Clipping uses seed mismatches `2`, palindrome threshold `30`, and simple threshold
`10`; the paired-end form adds minimum adapter length `8` and `keepBothReads=TRUE`.
The sliding window is four bases with an average-quality threshold of 20.
`--sequencer-source none` removes the adapter-clipping and initial `MINLEN:60`
steps, retaining the sliding-window and adaptive final length filter.

Passing `--trimmomatic-options` **replaces** this automatically assembled list;
it does not merely add one more operation. Likewise, `--max-memory` controls
Trimmomatic's Java heap. Nextflow's `memory` request and `params.max_memory`
are separate resource settings and do not automatically change `-Xmx500m`.

### Tandem Repeats Finder defaults

Repeat filtering runs by default, even when the command does not include
`--run-trf`. That flag is a legacy opt-in spelling; `--bypass-trf` disables the
default repeat-filtering stage. Trimmomatic's `--bypass-trim` is a separate switch.

| KneadData flag | Value | TRF interpretation |
| --- | ---: | --- |
| `--match` | 2 | Match weight |
| `--mismatch` | 7 | Mismatch penalty |
| `--delta` | 7 | Indel penalty |
| `--pm` | 80 | Match probability |
| `--pi` | 10 | Indel probability |
| `--minscore` | 50 | Minimum reported alignment score |
| `--maxperiod` | 500 | Largest reported repeat period |

The TRF option sequence is `2 7 7 80 10 50 500 -h -ngs`. KneadData converts
inputs to FASTA and invokes its `kneaddata_trf_parallel` helper with
`--nproc <threads>`. The base paired-end wrapper requests one process per task
CPU and one nested-tool thread. The `form_docker` override instead uses one
process and eight nested-tool threads.

### Bowtie2 and paired-read decontamination defaults

The default search preset is **`--very-sensitive-local`**. KneadData adds
`--phred33` and forwards the allocated thread count; the matching hg39T2T index
is discovered from the reference directory. Local alignment allows soft clipping.
Bowtie2 remains the host-search engine unless `--run-bmtagger` is explicitly set.

For paired input, `--decontaminate-pairs` defaults to **`strict`**: if either mate
aligns to the host, the pair is removed. `lenient` removes a pair only when both
mates align; `unpaired` treats mates independently. Single-end input uses the
unpaired mode. `--reorder` is not enabled by default. Multiple reference
searches are serial under the `form_docker` profile's one-process override.

An explicit `--bowtie2-options` value replaces the default preset list; include
the intended preset if retaining it. FastQC at the beginning/end and
`--run-trim-repetitive` are also opt-in. Trimmomatic adapter/quality trimming,
TRF filtering, and Bowtie2 host depletion run without those FastQC flags.

### DNAnexus site resources and reference placement

The repository does not yet contain a `dnanexus` profile. The following values
come from an inspected neighboring deployment and are planning evidence only.
A future FORM profile must carry the approved hg39T2T reference and the locked
Hugemiler tool versions.

| Setting | Generic bioBakery default | Inspected DNAnexus site setting |
| --- | --- | --- |
| CPUs for each QC task | `8 × task.attempt`, capped by `max_cpus` | **8**, fixed; command receives `--threads 8` |
| Memory | `16 GB × task.attempt`, capped by `max_memory` | **28 GB**, fixed |
| Time | `8 h × task.attempt`, capped by `max_time` | Inherited from the generic QC selector |
| Worker instance | Executor-dependent | `mem3_ssd2_v3_x16` |
| Queue limit | Executor-dependent | `executor.queueSize = 50` across tasks |
| Docker UID/GID | Site-dependent | `-u $(id -u):$(id -g)` |
| Reference placement | `host_genome` must be visible to the task | Neighboring deployment binds an in-task database directory; this is not a current FORM parameter |
| Additional KneadData options | Empty | No tool-option override in the inspected site configs |

The generic caps are `max_cpus: 32`, `max_memory: 128.GB`, and
`max_time: 240.h`. The fixed site CPU/memory settings do not call `check_max()`;
lowering those generic caps alone does not lower the site's fixed requests.
The inherited retry policy permits two retries for selected resource/signal
exit statuses (`125, 143, 137, 104, 134, 139`); other failures use `finish`.

Reference download/bind settings govern **where** the database becomes visible.
They do not change Bowtie2 sensitivity or the trimming/TRF defaults. Older
neighboring `hg37dec` paths/images are legacy configuration and must not be
carried forward as FORM's selected host reference. The
[host-reference page](../reference/kneaddata-host.md#runtime-placement) documents
the dedicated T2T directory and the remaining deployment handoff.

To restate the current biological defaults explicitly in a run YAML:

```yaml
run_qc: true
kneaddata_bypass_trim: false
kneaddata_remove_intermediate_files: true
kneaddata_options: >-
  --sequencer-source NexteraPE
  --quality-scores phred33
  --decontaminate-pairs strict
  --bowtie2-options='--very-sensitive-local'
```

This leaves adaptive Trimmomatic settings and default TRF parameters intact.
Choose an adapter setting appropriate to the actual library if it differs from
the configured default. These controls belong in the YAML; they do not add
fields to FORM's reads-folder-only pipeline schema.

## Running outside DNAnexus

Use the `form_docker` profile with a site profile, for example
`-profile local,form_docker`. The [README](https://github.com/gutz-technologies/form-nextflow-pipeline#quick-start-download-hg39t2t-and-run-kneaddata)
gives the complete steps: image and database sources, download, checksum,
run, and log check.

The image (like the pinned MetaPhlAn and HUMAnN images) starts with a dxfuse entrypoint (`/usr/local/bin/dx-reference-entrypoint.sh`)
that mounts DNAnexus references. Off DNAnexus, set `DXFUSE_ENABLED=false` in the
container environment; `form_docker` does this. Without it, every task fails with
`DNAnexus references: set DX_REFERENCE_PROJECT or forward DX_PROJECT_CONTEXT_ID`.
The image's default user is `mambauser` (UID 57439), so `form_docker` also runs
containers as the launching user.

A 2026-11-20 test run with `-profile local,form_docker` used 2,000 read pairs
simulated from T2T chromosome 8 and 2,000 random pairs. KneadData removed all
2,000 human pairs and kept all 2,000 random pairs. The task reported
KneadData `0.12.0` and Bowtie2 `2.5.5`.
